## What could go wrong with this change
- **The repo goes public and the decisions ledger and step folders become world-readable** · likelihood high (it is the plan) · impact low · noticed by: anyone can open github.com/jmcneil86043/f3l-series-website · mitigation/rollback: accepted in the 2026-10-15 ledger line; before John flips visibility, task 3's output notes confirm `git log -p | grep -E '^\+F3L_FTP_PASSWORD=.'` is empty on every branch, and the 2026-09-15 history rewrite already removed `smartftp.json`; the stale step branches (`step/RbsRQzYp-…`, `step/6cilqSP5-…`) are part of what becomes public, so delete any that are not wanted first.
- **Pages publishes from the wrong source** (someone sets the source to `main` or `/docs`) · likelihood low · impact medium (ledger and step folders served on the site) · noticed by: `deploy/verify.sh` check 13 (four 404 probes) FAILs · mitigation/rollback: set the source back to `gh-pages` in Settings → Pages; the README states the rule.
- **A push to `gh-pages` drops `CNAME`** (a hand push from a checkout of the branch, or the script changed) · likelihood low · impact medium (custom domain silently cleared; site answers only at github.io) · noticed by: dry run's live check reports every file differs; Settings → Pages shows no custom domain · mitigation/rollback: the script writes `CNAME` on every publish and the tests assert it; re-run `--upload`, re-enter the domain in Settings.
- **The live check hammers the old host or the 35 MB fetch is slow** · likelihood medium · impact low · noticed by: dry runs take tens of seconds, or print `Live: not checked (HTTP 465)` pre-cutover · mitigation/rollback: it never changes the exit code; the design's Open decisions name the HEAD-based variant.
- **Cutover before the Pages certificate exists** leaves the www name on Pages with a certificate warning for minutes to an hour · likelihood medium · impact low · noticed by: browser warning, verify check 8 FAIL · mitigation/rollback: runbook step 10 says wait for "issued" before Enforce HTTPS; if it does not issue within an hour, check the zone for stray A/AAAA/CNAME records (C5) or put the two records back (five minutes at TTL 300).
- **The apex A records or the `www` CNAME are entered wrong, or an MX/TXT record is touched while editing the zone** · likelihood low · impact high (mail via Mailgun breaks) · noticed by: verify check 9 before/after diff of MX and TXT differs · mitigation/rollback: restore from the §12.1 values written in the hand-off; MX/TXT are not to be opened at all.
- **A `--upload` from a worktree on an unmerged branch publishes content that `main` does not have** · likelihood medium · impact low · noticed by: the gh-pages commit trailer names a non-`main` source; the dry run from the clone after merge shows changes · mitigation/rollback: same property the FTP deploy had; runbook step 8 runs the dry run from the clone after the merge and publishes if it differs.
- **Task 1's merge of the hosting branch conflicts with later edits on that branch** (John amends `step/DJy1ViGr-…` before merging it to `main`) · likelihood low · impact low · noticed by: merge conflict at `/steprunner-merge` time · mitigation/rollback: ordinary conflict resolution in the ledger file; no site file is involved.
- **The dirty guard refuses `--upload` on a machine where git cannot run** · likelihood low · impact low · noticed by: exit 2 with the existing message · mitigation/rollback: unchanged from today; `--allow-dirty` is the override and the trailer records `Source-Dirty: unknown`.
- **Stale `~/.config/f3l-series-website/deploy.env` on Bishop still holds the FTP password** · likelihood high · impact low (ignored by the new script, but a secret on disk for a host being abandoned) · noticed by: the README says the file is now optional · mitigation/rollback: John deletes it or replaces it with the new example; 1Password keeps the item until the §13 card.
